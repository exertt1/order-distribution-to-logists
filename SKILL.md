# Навык: распределение заказов между логистами

## Когда применять

Применяй навык, если одновременно выполнены условия:

1. Пользователь приложил **три Excel-файла в формате `.xlsx`** (или `.xlsm`):
   - выгрузка ФУЛ из 1С (по строке на ФУЛ);
   - реестр Cloud (история заказов);
   - список сотрудников из 1С (ФИО, должность, текущее состояние, таб. №).
2. Сообщение пользователя **пустое** или не содержит описания задачи —
   это штатный режим запуска «приложил файлы и отправил».
3. Пользователь не просит что-то другое (не просит изменить правила,
   не просит записать данные в Cloud/1С, не просит отправить уведомления).

Ограничения по входу, которые нужно проверять до запуска:

- **Старый `.xls` не поддерживается** (читается через openpyxl). Если приложен
  `.xls` — попроси пересохранить в `.xlsx`.
- Файлов должно быть ровно три и они должны различаться по смыслу
  (ФУЛ / Cloud / сотрудники). Если файлов меньше трёх — скрипт не запускай,
  перечисли, каких не хватает.
- Читается **активный лист** каждого файла, заголовки — в **первой строке**.

## Как запустить

Скрипт навыка — `main.py` в каталоге проекта `Intern_Project`.
Запускай его одним вызовом, передавая пути аргументами:

```powershell
cd C:\Users\aidar\PycharmProjects\Intern_Project
.\.venv\Scripts\python.exe main.py `
  "C:\путь\выгрузка_ФУЛ.xlsx" `
  "C:\путь\реестр_Cloud.xlsx" `
  "C:\путь\сотрудники.xlsx" `
  "C:\путь\папка_результата"
```

- 1-й, 2-й, 3-й аргументы — пути к xlsx: ФУЛ, Cloud, сотрудники.
- 4-й аргумент — **каталог** результата (не имя файла). Необязательный,
  по умолчанию `./results`. Каталог создаётся автоматически.
- Итоговый файл всегда называется `result_cloud_update.xlsx`
  внутри этого каталога. Пути в кавычках — из-за пробелов.
- Скрипт можно вызывать и как `python Intern_Project\main.py ...` из родительского
  каталога: импорты плоские, но sys.path берётся от каталога скрипта, поэтому
  это работает. Относительные пути к файлам при этом считаются от текущего каталога.
- Код возврата: `0` — успех, `1` — не хватило аргументов, не найден входной
  файл, не создался каталог или упал сам процесс.

## Что делает скрипт

1. Читает три файла. **Колонки находит по названиям заголовков** (сравнение после
   `strip`, точное, без распознавания опечаток и переименований). Лишние колонки
   игнорирует, порядок колонок не важен, пустые строки пропускает.
   Обязательные колонки (иначе скрипт падает с ошибкой):
   - ФУЛ: `Номер`, `Комментарий`, `Контрагент`;
   - Cloud: `Заказ`, `Поставщик`, `Логист`, `статус`;
   - сотрудники: `Наименование`, `Должность`, `Текущее состояние`.
2. Достаёт **номер заказа** из колонки `Комментарий` выгрузки ФУЛ регуляркой
   `S\d+` (первое вхождение). Нет номера — строка попадает в `Attention Required`,
   в `New Orders` не пишется.
3. Помечает **повторные отправки**: номер заказа уже есть в Cloud (сравнение после
   `strip` + нижний регистр). Для повтора новая строка Cloud **не создаётся**,
   в описании пишется `Повторная отправка ФУЛа, <дата ФУЛ в формате ДД.ММ.ГГГГ>`
   (если дату ФУЛ распарсить не удалось — исходная строка, без выдумывания).
4. Определяет **группу** по двум полям выгрузки ФУЛ:
   - `Способ доставки` = `air` (без учёта регистра) → группа **AIR** —
     специалист по авиаперевозкам;
   - не `air` и `Страна` ∈ {`Китай`, `China`, `CN`, `Гонконг`, `Hong Kong`, `HK`} →
     группа **VED** — специалист по работе с ВЭД документацией;
   - не `air` и страна любая другая → группа **MULTI** — специалист
     по мультимодальным перевозкам;
   - `Способ доставки` пуст → **группа не определяется**, строка уходит
     в `Attention Required` и в распределении не участвует.
5. Отбирает **кандидатов** из справочника сотрудников:
   - группа по должности: содержит `авиа`/`air` → AIR; содержит
     `вэд`/`вед`/`экспорт`/`import` → VED; содержит `мульти` → MULTI; иначе группа
     не определяется (ассистенты, руководители, прочие);
   - доступен = в должности есть слово `специалист` **и** состояние ровно
     `работает` (без учёта регистра и пробелов). Поэтому автоматически
     исключаются `отпуск`, `больничный`, `уволен`, а также ассистенты
     и руководители группы.
6. Выбирает **одного логиста на пачку** (пачка = один поставщик + одна группа):
   - **предпочтительный по истории** — доступный специалист группы, у которого
     в Cloud больше всего заказов этого поставщика;
   - если такого нет (новый поставщик, 0 совпадений) — **наименее загруженный**
     специалист группы по числу заказов в статусе «в работе» в Cloud
     (при равной загрузке берётся первый по порядку в справочнике);
   - поставщик сравнивается с точностью до регистра, пробелов и пунктуации:
     `Nike Inc.`, `NIKE INC` и `nike  inc` — один поставщик;
   - имя логиста из Cloud сопоставляется с ФИО из 1С тоже строго (нижний регистр +
     сжатие пробелов). `Иванов И.И.` и `Иванов Иван Иванович` — **разные** записи;
   - в группе нет доступных специалистов → логист не назначается, строка уходит
     в `Attention Required` (в другую группу заказ **не передаётся**).
7. Пишет результат в Excel — листы и колонки описаны ниже.

## Формат результата

Файл `<каталог результата>\result_cloud_update.xlsx`, три листа.

**`New Orders`** — новые строки для реестра Cloud, 12 колонок в порядке реестра:
`Заказ`, `Поставщик`, `Бренд`, `Логист`, `статус`, `дата подтверждения`,
`cut-off`, `Дата получения УЛ`, `Страна отправления`, `Способ доставки`,
`Документы получены (дата)`, `Комментарий`.

Как заполняются:

- `Заказ` — номер, извлечённый из комментария ФУЛ; `Поставщик` — как в выгрузке
  ФУЛ (`Контрагент`); `Бренд` — `Бизнес единица`; `Логист` — назначенный специалист
  (ФИО как в справочнике 1С);
- `статус` — всегда `в работе`; `дата подтверждения`, `Документы получены (дата)`,
  `Комментарий` — **пустые** (заполняет человек/Cloud);
- `cut-off` — из `Cut-off date`, `Дата получения УЛ` — из `Дата` выгрузки ФУЛ;
  обе даты приводятся к формату `ДД.ММ.ГГГГ`, а нераспознанное значение
  переносится как есть;
- `Страна отправления` — из `Страна`, `Способ доставки` — из `Способ доставки`.
- Пустые поля, которых нет в источнике, остаются пустыми. Значение `не определено`
  подставляется только в колонку `Логист` и на практике не появляется: строка
  без логиста уходит на лист `Attention Required`.

**`Duplicates`** — повторные отправки: `Order ID`, `FUL Number`,
`Action Description` (текст вида «Skip creation. Update comment in existing
record: 'Повторная отправка ФУЛа, ДД.ММ.ГГГГ'»).

**`Attention Required`** — строки, требующие ручного разбора:
`Order ID`, `FUL Number`, `Status` (`ERROR`, если не извлечён номер заказа,
иначе `WARNING`), `Selected Logist` (`None`, если не назначен),
`Reason/Warnings` (причины через `; `, **текст причин — английский**: например
`Could not extract Order ID from comment.`,
`No available staff in VED group`, `Cannot determine logistics group due to
missing data`).

## Что пока НЕ реализовано

Эти пункты из бизнес-требований в коде отсутствуют — не обещай их пользователю
и не выдавай их за выполнение:

- листы **«Возможные пропуски»** (ФУЛ, которых нет в Cloud, хотя дата ФУЛ раньше
  последней даты Cloud) и **«Журнал решений»** (основание выбора логиста по каждому
  ФУЛ) — не формируются;
- названия листов — английские (`New Orders`, `Duplicates`, `Attention Required`),
  а не русские из ТЗ;
- **повтор внутри одной пачки** (один номер заказа дважды в самой выгрузке ФУЛ)
  не отлавливается — проверяется только наличие заказа в Cloud;
- сопоставление коротких имён логистов Cloud с полными ФИО 1С по «фамилия +
  инициалы» не делается (см. п. 6) — при несовпадении написаний всегда сработает
  правило «наименее загруженный»;
- пустая `Страна` при не-`air` не считается аномалией: заказ молча уходит в MULTI;
- `.xls`, несколько листов в одном файле, авто-определение колонок по смыслу.

## Технические заметки

- Точка входа — `main.py` (`run_agent`), модули: `reader.py`, `logic_engine.py`,
  `writer.py`, `models.py`, `constants.py`, `utils.py`. Импорты плоские:
  модули должны лежать рядом с `main.py`.
- `parser.py` — **устаревший дубль** логики (содержит ошибки: неопределённые
  `group_type`, `delivery_method`, отсутствующий импорт `Optional`).
  Нигде не импортируется; не используй его и не переноси его код.
- В `utils.py` остался второй, неиспользуемый `select_logist` с необъявленным
  типом `CloudOrder` в аннотации. Работает только на Python 3.14 (ленивые
  аннотации) — на 3.12 и ниже импорт `utils` упадёт с `NameError`.
- Проверка на тестовых данных:
  `main.py test_ful.xlsx test_cloud.xlsx test_employees.xlsx .\out_check`.

## Жёсткие правила

- Никогда не выдумывай номер заказа, страну, способ доставки, группу или логиста.
  Нет данных — строка идёт в `Attention Required` с указанием причины.
- Не записывай ничего в Cloud и 1С, не отправляй уведомления: навык только
  формирует Excel-файл.
- Не меняй правила распределения по ходу задачи: если пользователь просит другое —
  это уже не этот навык, а отдельная правка кода.
