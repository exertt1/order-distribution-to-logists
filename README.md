# order-distribution-to-logists

AI-агент для [GigaCowork](https://giga.chat), который распределяет новые
упаковочные листы (ФУЛ) из выгрузки 1С между логистами и готовит строки
реестра заказов Cloud строго по его форме.

Тестовое задание на позицию «Разработка агентов на GigaCowork».
Все данные синтетические, внешних интеграций нет: агент работает только
с тремя приложенными файлами Excel и отдаёт один файл результата.

Python 3 · openpyxl · без сети и внешних сервисов

## Задача

Каждый новый ФУЛ сотрудник вручную переносит из 1С в Cloud и подбирает логиста
по цепочке «тип перевозки → группа специалистов → поставщик → доступность →
текущая загрузка». Около 65 ФУЛ в день, заказы приходят пачками; при отпусках,
увольнениях и повторных отправках легко ошибиться.

Агент делает это сам: сотрудник прикладывает три выгрузки и отправляет
**сообщение без текста** — навык определяет новые ФУЛ, группу и логиста,
готовит строки Cloud и подсвечивает то, что требует решения человека.

Решения о группе и логисте принимает **детерминированный скрипт**; языковая
модель запускает его и пересказывает результат — так ответ воспроизводим
и каждое назначение объяснимо.

## Что на выходе

Один файл `result_cloud_update.xlsx`, пять листов:

| Лист | Содержимое |
|---|---|
| `Новые строки Cloud` | 12 колонок строго в форме реестра: заказ, поставщик, бренд, логист, статус, дата подтверждения, cut-off, дата получения УЛ, страна, способ доставки, документы, комментарий |
| `Повторные отправки` | повторы с готовым текстом «Повторная отправка ФУЛа, ДД.ММ.ГГГГ» |
| `Возможные пропуски` | ФУЛ, которых нет в Cloud, хотя они пришли раньше последней записи |
| `Требует внимания` | что не удалось распределить, причина и что сделать |
| `Журнал решений` | по каждому ФУЛ: группа, логист, категория, основание выбора, пояснение |

Ответ в чате — короткая сводка: сколько новых строк, повторов, пропусков
и вопросов.

## Правила

| Шаг | Правило |
|---|---|
| Группа | `air` → авиаперевозки; не `air` + Китай/Гонконг → ВЭД; не `air` + другая страна → мультимодальные; нет способа доставки или нет страны при не-`air` → группа не определена |
| Кто может получить заказ | должность содержит «специалист» (ассистенты и руководители исключены) и состояние ровно «Работает» (отпуск, больничный, увольнение — нет) |
| Предпочтительный логист | у кого больше заказов этого поставщика в Cloud; поставщик сравнивается без учёта регистра, пробелов и знаков (`Nike Inc.` = `NIKE INC`) |
| Иначе | наименее загруженный доступный специалист группы по заказам «в работе» |
| Пачка | один поставщик + одна группа = один логист |
| Повтор | заказ уже в Cloud или номер встретился в пачке → строка не создаётся, только комментарий с датой ФУЛ |
| Нет логистов в группе | заказ остаётся без логиста, в другую группу не передаётся |
| Нет данных | пишется «не определено», значение не выдумывается |

Подробно, с допущениями и порядком разрешения ничьих — [`skill/references/rules.md`](skill/references/rules.md).

## Структура

```
skill/                     навык для GigaCowork (то, что загружается в платформу)
  SKILL.md                 инструкция для модели: когда применять, как запускать
  system_prompt.txt        системный промпт агента
  scripts/                 код: main, constants, utils, models, reader, logic_engine, writer
  references/              справочник правил и шаблон формы реестра
data/
  generate.py              генератор синтетики и эталона (детерминированный)
  ful.xlsx cloud.xlsx employees.xlsx   входные данные: 20 ФУЛ, 36 заказов, 10 человек
  expected.xlsx            эталон: что агент обязан сделать по каждому ФУЛ
tests/
  run_metrics.py           три прогона и сравнение с эталоном
  run_robustness.py        файлы с другим порядком колонок и именем листа
  metrics_report.md        отчёт по метрикам
docs/
  report.md                вопросы заказчику, алгоритм, допущения, метрики (текст для pdf)
  run_log.txt              лог прогона
build.py                   сборка dist/agent.zip и dist/data.zip
```

## Быстрый старт

```bash
pip install openpyxl

python data/generate.py        # пересоздать данные и эталон
python build.py                # собрать dist/agent.zip и dist/data.zip

python skill/scripts/main.py data/ful.xlsx data/cloud.xlsx data/employees.xlsx out
python tests/run_metrics.py    # метрики против эталона
python tests/run_robustness.py # устойчивость к «чужим» файлам
```

Запуск навыка в платформе:

```bash
python scripts/main.py "<ФУЛ.xlsx>" "<Cloud.xlsx>" "<Сотрудники.xlsx>" "<папка результата>"
```

Коды возврата: `0` — успех, `1` — нет аргументов или файла, `2` — файл не читается
(например, нет обязательных колонок).

## Тестовые данные и эталон

20 ФУЛ, 36 заказов Cloud, 10 сотрудников. Эталон заполнен вручную по правилам —
не прогоном агента, иначе проверка подтверждала бы сама себя.

Заложенные ловушки: повтор из Cloud и повтор внутри пачки; новый поставщик;
предпочтительный логист в отпуске; вся группа недоступна (ВЭД); ФУЛ без номера
заказа, без способа доставки и без страны; ФУЛ раньше последней записи в Cloud;
один поставщик в пачке; поставщик в разном написании; ничьи по истории и по
загрузке; ассистент и руководитель в справочнике.

## Метрики

| Метрика | Значение |
|---|---|
| Совпадение с эталоном по всем полям | 20 из 20 ФУЛ — 100% |
| Точность по каждому полю (заказ, группа, логист, категория, комментарий, пропуск) | 100% |
| Подставлено значений там, где данных не было | 0 |
| Воспроизводимость (3 прогона) | идентичны |
| Время на пачку 20 ФУЛ | ≈ 0,001 с |
| Устойчивость к чужим файлам (обратный порядок колонок, лишняя колонка, лист «Лист1») | результат совпадает |

## Ограничения

- Ничего не записывает в Cloud и 1С, уведомления не отправляет.
- Заказ не передаётся в другую группу, если в своей нет доступных логистов.
- `.xls` читается только при установленном `xlrd`; основной формат — `.xlsx`.
- «Возможные пропуски» информационные: строка остаётся и в новых строках Cloud,
  решение — за сотрудником.

## Открытые вопросы к заказчику

Девять вопросов с разбором «кому / зачем / какое допущение принято» —
в [`docs/report.md`](docs/report.md): подсчёт истории поставщика, пачка при разных
группах, разрешение ничьих, дата в комментарии повтора, изменение статуса при
повторе, ФУЛ без номера, граница «возможных пропусков», заказ без страны при
`air`, неизвестный способ доставки.
