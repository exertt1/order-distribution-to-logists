# Навык: распределение заказов между логистами

## Когда применять

Применяй навык, если одновременно:

1. приложены **три Excel-файла** (`.xlsx`; `.xls` читается только при
   установленном `xlrd`):
   - выгрузка ФУЛ из 1С — по строке на упаковочный лист;
   - реестр Cloud — история заказов;
   - сотрудники из 1С — ФИО, должность, текущее состояние, табельный номер;
2. сообщение пользователя **пустое** или не содержит описания задачи
   (штатный запуск «приложил файлы и отправил»);
3. пользователь не просит ничего другого: не меняет правила, не просит
   записывать данные в Cloud/1С, не просит уведомлений.

Если файлов меньше трёх или они не читаются как Excel — **не запускай скрипт**,
а перечисли, каких файлов не хватает.

## Как запустить

Скрипты навыка лежат в `scripts/`. Запускается один скрипт, пути передаются
параметрами:

```bash
python scripts/main.py "<выгрузка_ФУЛ.xlsx>" "<реестр_Cloud.xlsx>" "<сотрудники.xlsx>" "<папка_результата>"
```

- первые три аргумента — входные файлы (ФУЛ, Cloud, сотрудники);
- четвёртый — **каталог** результата (не имя файла), необязательный,
  по умолчанию `./results`; каталог создаётся автоматически;
- результат всегда `<каталог>/result_cloud_update.xlsx`;
- код выхода: `0` — успех, `1` — не хватает аргументов или не найден входной
  файл, `2` — файл не прочитан (нет обязательных колонок и т.п.).

Скрипт печатает в stdout блок `=== ИТОГИ ===` и разбивку по группам,
повторам и строкам, требующим внимания. Эти числа берутся из вывода —
не пересчитывай их самостоятельно и не придумывай.

## Что делает скрипт

1. Читает три файла. **Колонки находит по заголовкам**, а не по номеру: лишние
   колонки игнорирует, порядок колонок не важен, имя листа не важно (берётся
   лист с наибольшим числом нужных заголовков). Обязательные колонки:
   - ФУЛ: `Номер`, `Комментарий`, `Контрагент`;
   - Cloud: `Заказ`, `Поставщик`, `Логист`, `статус`;
   - сотрудники: `Наименование`, `Должность`, `Текущее состояние`.
2. Достаёт **номер заказа** из комментария ФУЛ (`S0001234`). Номера нет —
   строка идёт в «Требует внимания» с причиной.
3. Отделяет **повторные отправки**: заказ уже есть в Cloud (сравнение без учёта
   регистра и пробелов) либо этот же номер встретился в пачке раньше. Для
   повтора строка Cloud не создаётся, готовый комментарий —
   `Повторная отправка ФУЛа, ДД.ММ.ГГГГ` (дата ФУЛ).
4. Определяет **группу**:
   - способ доставки `air` → авиаперевозки (страна не важна);
   - не `air` + страна Китай или Гонконг (`Китай`, `China`, `CN`, `Гонконг`,
     `Hong Kong`, `HK`) → ВЭД;
   - не `air` + другая страна → мультимодальные перевозки;
   - способ доставки не указан, либо не `air` и страна не указана → группа
     **не определена**, строка идёт в «Требует внимания» (в другую группу
     заказ не передаётся).
5. Отбирает **доступных специалистов** группы: в должности есть «специалист»
   (значит ассистенты и руководители исключены) и состояние ровно «Работает»
   (отпуск любого вида, больничный, увольнение — недоступен).
6. Выбирает логиста на **пачку** (один поставщик + одна группа = один логист):
   - **предпочтительный по истории** — у кого больше заказов этого поставщика
     в Cloud; поставщик сравнивается без учёта регистра, пробелов и знаков
     (`Nike Inc.` = `NIKE INC`);
   - предпочтительный логист недоступен или поставщик новый → **наименее
     загруженный** доступный специалист группы по числу заказов «в работе»;
   - ничья разрешается порядком сотрудников в выгрузке 1С;
   - в группе нет доступных — логист не назначается, строка в «Требует
     внимания»;
   - остальные ФУЛ того же поставщика в пачке получают того же логиста
     с основанием «один поставщик — один логист».
7. Ищет **возможные пропуски**: ФУЛ, которых нет в Cloud, хотя дата ФУЛ раньше
   последней даты движения заказа в Cloud (максимум по датам получения УЛ,
   подтверждения и получения документов; cut-off не учитывается — это будущая
   контрольная дата).
8. Пишет Excel из пяти листов (см. ниже) и печатает сводку.

## Формат результата

Файл `result_cloud_update.xlsx`, пять листов:

| Лист | Содержимое |
|---|---|
| `Новые строки Cloud` | 12 колонок строго в форме реестра: `Заказ`, `Поставщик`, `Бренд`, `Логист`, `статус`, `дата подтверждения`, `cut-off`, `Дата получения УЛ`, `Страна отправления`, `Способ доставки`, `Документы получены (дата)`, `Комментарий` |
| `Повторные отправки` | ФУЛ, заказ, дата ФУЛ, категория повтора, готовый текст в «Комментарий» |
| `Возможные пропуски` | ФУЛ, заказ, дата ФУЛ, последняя дата Cloud, поставщик, группа, логист, почему в списке |
| `Требует внимания` | ФУЛ, заказ, страна, способ доставки, группа, логист, причина, что сделать |
| `Журнал решений` | по каждому ФУЛ: группа, логист, категория, основание выбора, пояснение, признак пропуска, причина внимания, комментарий для Cloud |

Значения в новых строках: `статус` — всегда «в работе»; `дата подтверждения`,
`Документы получены (дата)` и `Комментарий` — пустые (их заполняет сотрудник
или Cloud); `cut-off` и `Дата получения УЛ` переносятся из выгрузки ФУЛ
без изменения значений (в ячейку формата ДД.ММ.ГГГГ). Где данных нет —
пишется **«не определено»**; ничего не додумывается.

## Как ответить пользователю

Короткий ответ по шаблону, числа — из вывода скрипта:

> Готово: 20 ФУЛ — **13 новых строк Cloud**, **2 повторные отправки**,
> **1 возможный пропуск**, **5 требуют внимания**.
> Файл: `result_cloud_update.xlsx`.
> Требуют решения: FUL-2026-007 и FUL-2026-008 — в группе ВЭД нет доступных
> логистов; FUL-2026-010 — нет номера заказа; FUL-2026-011 — нет способа
> доставки; FUL-2026-012 — нет страны.
> Обоснование по каждому заказу — на листе «Журнал решений».

Правила ответа: не пересчитывай числа самостоятельно; не обещай действий,
которых скрипт не делает (запись в Cloud/1С, уведомления); если файл не
прочитан — покажи ошибку скрипта и что нужно исправить в выгрузке.

## Жёсткие ограничения

- Решение о группе и логисте принимает только скрипт; модель его не меняет.
- Ничего не записывается в Cloud и 1С, уведомления не отправляются,
  внешние сервисы и сеть не используются.
- Заказ никогда не передаётся в другую группу, если в своей нет логистов.
- Справочники правил и шаблон формы реестра — в `references/`.
